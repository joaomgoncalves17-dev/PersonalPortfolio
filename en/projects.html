02 Planned

Hardened Linux web server

A Debian server exposed to the internet with only what it needs: key-only SSH, a restrictive firewall, automatic security updates and Nginx with HTTPS.

  • Debian
  • OpenSSH
  • nftables
  • fail2ban
  • Nginx
  • Let's Encrypt
  • Lynis

Goal

Put a service online with an attack surface that is small, known and documented.

What it covers

  • Key-only SSH, no root login and a separate admin user
  • nftables firewall denying everything by default, with fail2ban on SSH
  • Automatic security updates with unattended-upgrades
  • Nginx with a Let's Encrypt certificate and security headers
  • Lynis audit before and after, to measure the difference

What gets documented

  • Hardening checklist with the reason for each change
  • Lynis report before and after
  • Nginx and firewall configuration
03 Planned

Bash maintenance toolkit

Tested Bash scripts for a server's daily checks, run by systemd timers and reporting by email.

  • Bash
  • systemd
  • rsync
  • ShellCheck
  • Git

Goal

Replace the manual morning checklist with scripts that run on their own and only speak up when something is wrong.

What it covers

  • Health report: disk, memory, load, failed services and pending updates
  • User creation from CSV, with a temporary password that must be changed
  • rsync backup of /etc and home directories, with rotation
  • systemd timers instead of cron, with logs in the journal
  • Scripts checked with ShellCheck, using set -euo pipefail and a --dry-run mode

What gets documented

  • Git repository with README
  • --help output in every script
  • Sample report

  • mdadm

05 Planned

Network services on Linux

DNS, DHCP and time for a small office running on Linux, with a secondary DNS server for redundancy.

  • Debian
  • BIND9
  • Kea DHCP
  • chrony
  • dig

Goal

Understand core network services without a GUI and compare them with the same setup on Windows Server.

What it covers

  • BIND9 with an internal zone, primary and secondary servers with zone transfer
  • Kea DHCP with reservations and automatic DNS updates
  • chrony as the network's NTP server
  • Troubleshooting with dig and journalctl
  • Failure test: switch off the primary DNS and confirm the network still resolves

What gets documented

  • Zone files and configuration
  • Address and reservation table
  • Comparison with Windows Server DNS and DHCP
