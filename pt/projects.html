Projetos

Projetos de laboratório que reproduzem o trabalho de uma equipa de infraestrutura. Os planeados vão ser feitos por esta ordem e cada um fica publicado com a documentação.

01 Concluído

Domínio híbrido Windows e Linux

Rede de uma pequena empresa montada de raiz, com Active Directory, servidores Linux e um plano de recuperação testado.

  • Windows Server
  • Active Directory
  • Debian
  • Samba
  • Backups

Objetivo

Simular a infraestrutura de uma pequena empresa e conseguir recuperá-la depois de uma falha.

O que inclui

  • Controlador de domínio Windows Server com DNS e DHCP
  • Unidades organizacionais, grupos e políticas de grupo por departamento
  • Servidor Linux com partilhas de ficheiros e servidor web
  • Cópias de segurança automáticas e teste de restauro completo

O que fica documentado

  • Diagrama da rede
  • Plano de recuperação escrito
  • Lista de GPO aplicadas
02 Planeado

Servidor web Linux com hardening

Um servidor Debian exposto à internet só com o necessário: SSH apenas com chaves, firewall restritiva, atualizações de segurança automáticas e Nginx com HTTPS.

  • Debian
  • OpenSSH
  • nftables
  • fail2ban
  • Nginx
  • Let's Encrypt
  • Lynis

Objetivo

Pôr um serviço online com uma superfície de ataque pequena, conhecida e documentada.

O que inclui

  • SSH só com chaves, sem login de root e com utilizador de administração separado
  • Firewall nftables a negar tudo por defeito, com fail2ban no SSH
  • Atualizações de segurança automáticas com unattended-upgrades
  • Nginx com certificado Let's Encrypt e cabeçalhos de segurança
  • Auditoria com Lynis antes e depois, para medir a diferença

O que fica documentado

  • Checklist de hardening com o motivo de cada alteração
  • Relatório Lynis antes e depois
  • Configurações do Nginx e da firewall
03 Planeado

Kit de manutenção em Bash

Scripts Bash testados para as verificações diárias de um servidor, corridos por timers do systemd e com relatório por email.

  • Bash
  • systemd
  • rsync
  • ShellCheck
  • Git

Objetivo

Trocar a lista de verificação manual da manhã por scripts que correm sozinhos e só avisam quando algo está mal.

O que inclui

  • Relatório de estado: disco, memória, carga, serviços falhados e atualizações pendentes
  • Criação de utilizadores a partir de CSV, com palavra-passe temporária e mudança obrigatória
  • Backup de /etc e das pastas pessoais com rsync e rotação
  • Timers do systemd em vez de cron, com registos no journal
  • Scripts validados com ShellCheck, com set -euo pipefail e modo --dry-run

O que fica documentado

  • Repositório Git com README
  • Ajuda --help em cada script
  • Exemplo de relatório
04 Planeado

Armazenamento com RAID, LVM e NFS

Servidor de ficheiros com discos em espelho e volumes flexíveis, incluindo uma falha de disco simulada e a sua substituição.

  • Ubuntu Server
  • mdadm
  • LVM
  • XFS
  • NFS
  • Samba

Objetivo

Praticar as tarefas de disco que aparecem em produção: aumentar um volume, trocar um disco avariado e voltar a um snapshot.

O que inclui

  • RAID 1 com mdadm e LVM por cima
  • Aumentar volumes e sistemas de ficheiros sem desligar o servidor
  • Snapshots LVM antes de cada alteração
  • Partilhas NFS e Samba com permissões por grupo e quotas
  • Falha de disco simulada e reconstrução do RAID, com o tempo registado

O que fica documentado

  • Esquema dos discos e volumes
  • Procedimento de substituição de disco
  • Registo do teste de falha
05 Planeado

Serviços de rede em Linux

DNS, DHCP e hora para um pequeno escritório a correr em Linux, com um DNS secundário para redundância.

  • Debian
  • BIND9
  • Kea DHCP
  • chrony
  • dig

Objetivo

Perceber os serviços de rede base sem interface gráfica e comparar com a mesma montagem em Windows Server.

O que inclui

  • BIND9 com zona interna, servidor primário e secundário com transferência de zona
  • Kea DHCP com reservas e atualização automática do DNS
  • chrony como servidor NTP da rede
  • Diagnóstico com dig e journalctl
  • Teste de falha: desligar o DNS primário e confirmar que a rede continua a resolver

O que fica documentado

  • Ficheiros de zona e configurações
  • Tabela de endereços e reservas
  • Comparação com DNS e DHCP do Windows Server
06 Planeado

Registos centralizados e auditoria

Todos os servidores enviam os registos para um só sítio, com retenção definida e alertas para logins falhados e uso de sudo.

  • Debian
  • rsyslog
  • journald
  • logrotate
  • auditd

Objetivo

Responder a "quem fez o quê, e quando" em qualquer servidor sem entrar em cada um.

O que inclui

  • rsyslog a enviar registos por TLS para um servidor central
  • journald persistente com limites de tamanho
  • Política de retenção com logrotate
  • Regras auditd para sudo e alterações em /etc/passwd e /etc/sudoers
  • Relatório diário de logins SSH falhados e comandos sudo

O que fica documentado

  • Diagrama da arquitetura
  • Política de retenção
  • Regras auditd comentadas
  • Exemplo de relatório diário
